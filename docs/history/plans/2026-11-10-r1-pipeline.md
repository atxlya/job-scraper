# R1 — Pipeline + first 28 companies — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A worker that runs every 30 minutes, scrapes 28 companies (Google, NVIDIA and Barclays, plus everything on Workday, Eightfold and Oracle HCM), stores every job in SQLite, classifies tech internships, asks Gemini to check eligibility, and sends Telegram alerts. It runs under Docker Compose on the Mac and on the Pi.

**Architecture:** Async Python. One polite HTTP client is shared by all adapters. Each adapter turns one site into `ListingResult`/`RawJob`. The pipeline upserts, dedupes and detects closed jobs. Rules classify jobs first, and a paced Gemini queue handles the rest. The Telegram service sends alerts and then edits them. APScheduler runs in its own `worker` container, and FastAPI serves only `/healthz` in R1 (the dashboard comes in R2).

**Tech Stack:** Python 3.12, uv, httpx (+respx in tests), pydantic v2 + pydantic-settings, SQLAlchemy 2 + Alembic, SQLite (WAL), selectolax, PyYAML, APScheduler 3.x, google-genai, FastAPI + uvicorn, pytest + pytest-asyncio, ruff, Docker Compose.

**Spec:** [docs/DESIGN.md](../../DESIGN.md) and [docs/companies.md](../../companies.md). Read both before starting any task.

## Global Constraints

- Python `>=3.12`. Package manager `uv`. Lint with `ruff check` + `ruff format --check`, which must be clean at every commit.
- **robots.txt is checked before every request. A disallowed URL is never fetched.** Bot protection is never worked around. No Playwright in R1.
- Per-host minimum interval between requests: **2.5 s** (setting `HTTP_MIN_INTERVAL_S`). Timeout 20 s. Up to 4 retries with exponential backoff and jitter on timeout / 429 / 5xx, honouring `Retry-After`.
- User-Agent: `job-scraper/0.1 (personal, non-commercial; respects robots.txt)`. No personal details in requests.
- **No invented jobs.** Every test fixture is a response recorded from the live endpoint (`scripts/record_fixture.py`), trimmed for size, never hand-written.
- Times are stored as UTC-aware `datetime`. Display and scheduling use `Asia/Kolkata`.
- Google: **only page 1** of results. A request URL containing `page=` must never be produced.
- Gemini: model setting `GEMINI_MODEL=gemini-3.5-flash-lite`, free tier only, **≤ 5 requests/min**, daily cap `GEMINI_DAILY_CAP` (default 250), counted per Pacific-time day (resets at midnight PT = 13:30 IST).
- A job is alerted **at most once** (unique `alerts.job_id`). Burst threshold: **more than 10** new internships in one run are sent as one grouped message.
- Closed means: the detail fetch returns `Gone`, **or** the job is missing from **2 consecutive complete** full sweeps.
- Secrets only come from `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GEMINI_API_KEY`). `.env` is git-ignored, and `.env.example` is committed.

## Review Focus

1. **A site returns 200 but no or garbled data** (a maintenance page, or Google changing its arrays). This must count as a *failed* run, never as "every job closed". Tests: Task 6 (`test_partial_result_never_closes`), Task 4 (`test_parse_error_marks_failed`).
2. **The same job appears in two sources of one company** (Visa `Visa` + `Visa_Early_Careers`). It must be one job row and one alert. Test: Task 6 (`test_same_job_two_sources_one_row`).
3. **The Pi loses its network for hours.** Every source fails at once. Expect one combined "all sources failing — network?" warning, not 28 separate ones. Test: Task 9 (`test_all_sources_failing_sends_one_message`).
4. **Job titles containing `<`, `&` or emoji** must not break Telegram HTML parse mode. Test: Task 9 (`test_format_alert_escapes_html`).
5. **The API reads while the worker writes.** SQLite must not throw `database is locked`. Test: Task 1 (`test_concurrent_read_during_write`).
