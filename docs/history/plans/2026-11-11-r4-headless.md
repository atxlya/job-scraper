# R4 — The last seven sites (no headless browser needed) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 6 companies (61 supported in total): Tech Mahindra, LTIMindtree (RippleHire), Myntra (Spire2Grow), ShareChat (MyNextHire), Jio and Reliance. Urban Company moves to "Not supported". No Playwright: every one of the seven "group D" sites either works over plain HTTP or is blocked by robots.txt.

**Architecture:** Every adapter follows the R1 contract (`list_jobs` / `fetch_detail` → `RawJob`), registers in `ADAPTERS`, and makes every request through `PoliteClient`. One shared change comes first: `PoliteClient.post_form` plus a small ASP.NET WebForms helper (`app/adapters/aspnet.py`) for "postback" paging, which Tech Mahindra, Jio and Reliance use. The three JSON platforms (RippleHire, Spire2Grow, MyNextHire) get platform adapters configured per tenant; Tech Mahindra, Jio and Reliance get company adapters.

**Tech Stack:** Python 3.13, httpx via `PoliteClient`, selectolax (HTML), respx + pytest. React/TypeScript only for one label map.

**Spec:** [docs/DESIGN.md](../../DESIGN.md) §3 (scraping, politeness, "no headless browser where plain HTTP works", accuracy checks), §11 (testing), §12 (releases). Per-company list: [docs/companies.md](../../companies.md) "R4 — +7". Earlier decisions: [R2b-notes.md](../R2b-notes.md), [R3-notes.md](../R3-notes.md). Every endpoint below was probed live on **2026-11-11** through `PoliteClient` (robots.txt checked). The shapes, IDs, titles, counts and status codes quoted are from those responses.

## Global Constraints

- Python `>=3.13`, `uv`. `uv run ruff check` and `uv run ruff format --check` are clean at every commit (line length 100). `cd web && npm run check` is clean at every commit that touches `web/`.
- **No new dependencies.** No Playwright, no browser, no Docker change.
- **Every request goes through `PoliteClient`**: robots.txt before every request and redirect hop, per-host pacing, retries (DESIGN §3). No adapter creates its own httpx client.
- **Never fetched:** `www.urbanclap.com/api/*`; any `/error.aspx`, login, `frmLogin.aspx` or apply page; Tech Mahindra's "Apply/Shortlist" postback; RippleHire `/auth/` paths.
- **Encrypted query strings are used verbatim.** Jio and Reliance URLs carry values like `func=w+cpdiT6wL4=` and `desc=am1AraTXtX4/W/EJK6dzzw==`. Pass the whole URL as a string, as read from the page's `href` (HTML entities unescaped), and never rebuild it through `params=`.
- **Fixtures are recorded real responses** (`scripts/record_fixture.py`), never hand-written (DESIGN §11). A test may change one field of a loaded fixture to set up a case. Redirects are served as `httpx.Response(302, headers={"Location": …})` with the values pinned here.
- Titles, IDs and counts quoted from 2026-11-11 may have changed by the time a fixture is recorded. A test then uses the recorded value, and `R4-notes.md` says what changed. A changed *shape* (a missing marker, a different "not found" answer) is a finding to raise, not to code around.
- An adapter raises `ParseError` when a response lacks its expected shape or page marker, and returns `GONE` only for the answers D10 names.
- Times are UTC-aware (`app.adapters.base.utc`). Dates without a time (`"04 Nov 2026"`) are midnight UTC. Country codes are ISO 3166 alpha-2.
- `RawJob.platform_flags["intern"]` only from a site field that marks internships: ShareChat `employmentType == "intern"`, Myntra an `employmentType` containing `INTERN`.

## Review Focus

1. **A postback that lands on the wrong page.** WebForms paging posts the previous page's `__VIEWSTATE`; a stale or rejected one answers `302 → /error.aspx` or a different page. That must fail the run, not end the walk early with `complete=True` (which would count toward closing jobs). Tests: Task 1 `test_postback_redirect_raises`, Task 2 `test_wrong_page_raises`.
2. **Encrypted query values** (`+`, `/`, `=`) must reach the server unchanged. Turning `+` into `%2B` or a space would make Jio and Reliance answer the error page for every category. Tests: Task 6 `test_category_url_sent_verbatim`, Task 7 `test_results_url_sent_verbatim`.
3. **RippleHire's 500 for a missing job** must never become `GONE`; an outage would otherwise close every tracked LTIMindtree job. Test: Task 3 `test_detail_500_is_error_not_gone`.
4. **Tech Mahindra's newest jobs are on the last pages.** An incremental run that reads only page 1 would never alert. Test: Task 2 `test_incremental_reads_first_last_and_before_last`.
5. **Jio's category counts are the accuracy check.** A full run that reads fewer jobs than the counts must be `partial` (the runner's 2% rule), not ok. Test: Task 6 `test_reported_total_is_sum_of_chosen_categories`.

### Task 1: Form POSTs, the WebForms helper and the recorder

**Files:**
- Modify: `app/http/client.py`, `scripts/record_fixture.py`
- Create: `app/adapters/aspnet.py`, `tests/adapters/test_aspnet.py`

**Interfaces:**
- Produces:
  - `PoliteClient.post_form(url, data: dict[str, str], *, headers=None, follow_redirects: bool = True) -> httpx.Response` — `_request("POST", url, data=data, …)`, so robots, pacing, retries and redirect hops work as for `post_json`.
  - `aspnet.form_fields(tree: HTMLParser) -> dict[str, str]`: every `input[name]` whose `type` is missing, `hidden` or `text` (its `value`, else `""`), and every `select[name]` (its `option[selected]` value, else its first option's). Submit, button, checkbox and password inputs are left out.
  - `aspnet.postback_target(href: str) -> str`: the first argument of `javascript:__doPostBack('X','')`; `ParseError` if the href isn't one.
  - `async aspnet.postback(client, url: str, tree: HTMLParser, target: str, extra: dict[str, str] | None = None) -> HTMLParser`: `form_fields(tree) | {"__EVENTTARGET": target, "__EVENTARGUMENT": ""} | (extra or {})`, sent with `client.post_form(url, data, follow_redirects=False)`. Any status other than 200 → `ParseError(f"postback {target} answered {status} {Location}")`.
  - `aspnet.pages_shown(tree) -> tuple[int, int] | None`: `Showing (\d+) of (\d+) Pages` from the page text (Jio, Reliance), else `None`.
  - `record_fixture.py`:
    - `--form K=V` (repeatable): with `POST`, sends a form body instead of JSON.
    - `--step SPEC` (repeatable): after the GET, each step posts back on the previous answer and the last answer is saved. `SPEC` is `TARGET|K=V|K=V…`. `TARGET` is a control name, `label=TEXT` (the `postback_target` of the first `a[href^="javascript:__doPostBack"]` whose text is `TEXT`), or `select$=SUFFIX:VALUE` (the select whose name ends with `SUFFIX`, set to `VALUE` and used as the target).
    - `--drop-keys a,b,c`: removes those keys at any depth of a JSON answer before saving.
